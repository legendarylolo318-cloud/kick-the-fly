# How 3.0 was built and checked: decisions, known limits, review findings

3.0 was built over five days, each day's work by one author (Sonnet) and adversarially reviewed by another (Opus) before it was merged,
with a final release review. The day-by-day working notes (`HANDOFF_*.md`) were retired at release; git history keeps them. This page keeps
what lasts: the decisions that shape behavior, the limits a user or researcher should know, what was checked and how, and what has never
been verified. Feature documentation lives on each feature's page ([changelog.md](changelog.md) links them all).

## The rules every day followed

- **Validation identical.** `--headless --validate --sim-backend cpu` on the 3.0 branch was diffed against the previous baseline after every
  day and at release: every value identical except `created` and `seconds`. 21 tests, **12 PASS / 9 FAIL**, the same per test
  ([validation.md](validation.md)). No weight, time constant or threshold was tuned to make a test pass.
- **Pre-registration.** Every new assay's criteria were written into its module and committed before the first held-out run (seeds
  1000+); designs were chosen on exploration seeds. Failures are reported as failures (the four-field olfactory arena, race R2 and R3,
  the larva tests, the motor half of the grooming circuit, the E-PG compass).
- **Tags.** Every new behavior is tagged CONNECTOME (read off the wiring), GAME RULE (a rule written for the game) or MODEL PREDICTION (what
  the model then does), on screen, in the docs and in Lab > Model assumptions.
- **A regression test for every bug** a review found, checked to fail on the code before the fix (`tests/test_day*_review.py`,
  `tests/test_release_3_0.py`, `tests/test_layout_3_0.py`).
- **Long runs from frozen worktrees**, so a worker never imports code edited mid-run.

## Decisions (and why)

| question | decision | why |
|---|---|---|
| Neurodex: do calm discoveries count? | **No.** An untouched calm fly discovers nothing; a driven fly does. Old "at rest" entries load and keep their tag. | On the real pack the calm discoveries were spontaneous bursts of sensory types: background activity, not something a player did. |
| Neurodex key D (also walk-right in 3D) and kill cam `;` | Kept. In 3D the Neurodex opens on D only with the mouse free; old configs that used D keep it and start with the Neurodex unbound. | Every letter was taken; `c` is crouch. |
| Thermogenetics escape assay | A step, not a dose-response; kept and documented. | The step is DNp01's (two neurons at their refractory limit); smoothing it would be tuning to a result. |
| Imaging: F0 time constant, frame rate, GCaMP6 kernels | 30 s and 20 Hz defaults, both settings (GAME RULE); kernels are Chen et al. 2013's in-vivo single-spike numbers (6s 179/550 ms, 6f 45/142 ms). | No published value for the first two; the kernels are measured numbers. |
| Predators | Frog and mantis in the Chaos preset; the dragonfly in All and Lab (it hunts only a flying fly). A held-still fly escapes 0/30 strikes: kept as a MODEL PREDICTION, no strike slowed. | Making escapes happen would be tuning. |
| Streamer mode | `!tool` on, `!arena` and `!surgery` off by default; off in Lab mode; microphone and stream switches are never saved. | Nothing can start by itself. |
| Real neuron shapes (neuPrint skeletons) | Opt-in, asked once after the tutorial; cached shapes still load. | A network download should be the player's choice. |
| Personality cards | **Only measured cards are shown** ("card not measured" otherwise); a seed-drawn card was replaced everywhere. Old pet files keep the drawn card as `legacy_personality_card`, never shown. | A card must describe the brain it is shown for. |
| Race speed rule | Version 2: DNp09 against one fixed reference rate (4.32 Hz), not each fly's warm-up baseline. R1 now tests individuality (subtle 0.77, off 0.09); R2 and R3 FAIL and are reported. | Version 1 made the `off` control repeatable through a warm-up artefact (race R4 showed it). |
| Behavior rigs' LC10 tracking rule | Kept strong and deterministic (the duel's rule). | Making it noisier would be a game-rule change made after seeing results. |
| What's New | Shown once after an upgrade, after the loadout notice if a 2.13 config also gets that (one notice per launch); a fresh install never sees it. | The tutorial is a new player's welcome. |

## Known limits

- **Sensory inputs are delivered per screen frame** in the live game, so a slow brain gets more stimulus per simulated second (rain costs
  about 10-16% of real-time speed). Lab protocols and assays are lockstep and exact.
- **The larva pack** is optional and built from a separate download (docs/larva.md); its transmitter signs are a guess and its network idles
  at about 60 Hz, so both larva validation tests fail.
- **Rigs:** bar and stripe fixation are far tighter than real flies' (about 3 degrees), the transits are largely made by the edge rule, the
  tethered response saturates by the EMD stage's design (no speed tuning curve), and the olfactory arena gives an odor no valence. The rig's
  stripe deviation is a different metric from Colomb et al.'s (same 45-degree chance).
- **Mini-papers:** three papers were read as abstracts only (von Reyn 2014, Ohyama 2015, Tully & Quinn 1985); Shiu 2024's full text was searched
  for specific claims, not read line by line; Hampel 2015 and Colomb 2012 were read through page summaries plus targeted checks. A quick run
  (4 flies) cannot reach p < 0.01 and says so.
- **Duels** rarely end in a knockout (DNp35 rarely crosses its shooting threshold); no blaster or arena number was changed.
- **Weather and the kitchen are 3D only**; rain has no shelter under trees.
- **German** covers part of the interface; untranslated strings fall back to English.
- **Test memory:** files that build whole games keep 1-2 GB resident; `tools/run_tests.py` runs chunks with a memory guard.

## Never verified (as of 3.0.0)

- A physical gamepad (pad paths are driven by scripted button sets through the game's own code), a real microphone, a real Twitch
  connection, the system clipboard.
- GPU compute backends beyond the self-test's OpenGL probe; every reported number is the CPU reference backend's.
- `nwbinspector` on exported NWB files (they are read back with pynwb).
- A person playing a full session in a visible window (reviews used offscreen frames and short scripted windowed runs).

## What the reviews found (each fixed, with a regression test)

| review | highlights |
|---|---|
| Day 1 | Neurodex and share-code data bugs, bundle reruns, the D-key conflict made safe to rebind (25 regression tests). |
| Day 2 | Threading and state bugs in the live Lab pages, hostile protocol and share-code input, frames looked at for real (64 tests, 60 failing before). |
| Day 3 | A LiveInputs memory leak in the tests, predator and weather fixes, sources read directly (`tests/test_day3_review.py`). |
| Day 4 | The seed-drawn personality card (decision above), the rich-club null on the wrong degrees, undefined motif enrichment shown as nan, `params` silently ignored by four validation tests, Lab jobs collected by the wrong page, Cancel that did not cancel, hostile wallet files (45 tests, 41 failing before). |
| Release | See CHANGELOG.md, "Release review": rig and mini-paper bugs, citation corrections (Shiu 2024 uses MN9 itself; Colomb's metric differs), the order-dependent Neurodex test leak, text overlap and clipping across about 25 pages, page bugs found on the way (blank Classroom tabs, unreachable rig protocols, mislabelled asymmetry numbers, a false self-test failure), capped Neurodex toasts and the outdoor night sky. |

The 3.0 day 5 environment note still applies to machines like the one 3.0 was finished on: with Python 3.14 and no pygame wheel, a source
build of pygame lacked fonts and sound; `pygame-ce` in the virtual environment worked (`requirements.txt` was left unchanged).
