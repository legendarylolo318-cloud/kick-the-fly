# PORTING.md: Python → Rust + Bevy parity checklist

> **Where the Python code is.** This checklist was written while the Python game sat in `legacy-python/` on the port branch. That folder is
> not on `main`: every `legacy-python/...` path below is a path on the branch `python-legacy` (tag `python-3.1.1`) without that prefix, and the
> `make_*_reference.py` scripts are now in `tests/reference_tools/`. The old protocol files are in `tests/python_files/protocols/`.

Source of truth for the `bevy-port` branch. Every feature of the Python game (3.1.1, `kickthefly/`) is listed once, with the Python file
and function/class it lives in. Later steps tick items off. **Do not tick an item until the Rust version reproduces the Python behavior**
(for the simulator: the golden tests in `crates/fly_sim/tests/golden.rs`; for everything else: a test or a documented manual check).

Legend: `[x]` done and verified · `[~]` partly done (the note says what is missing) · `[ ]` not started.
Paths are relative to `legacy-python/kickthefly/` after the move (today: `kickthefly/`). `Tag` is the game's own honesty tag
(CONNECTOME / GAME RULE / MODEL PREDICTION, see `docs/connectome-and-game-rules.md`); a port must keep it on screen.

### 2.2 Neuron model (`sim/connectome/sim.py:LIFParams, LIFSim`, `backends.py:CPUBackend.step`)
- [x] Parameters: `dt_ms=5, tau_ms=20, v_thresh=1, v_reset=0, refractory_steps=2, syn_gain=6 (initial), ext_gain=4, bias=0.2, noise_std=0.05, target_rate_hz=5, gain_adapt=0.002, gain_bounds=(1.5,40)`.
- [x] Per-step order: `I = W·spikes_prev` → `drive = I*gain + bias + noise_bank[off..off+n] (+ ext_gain*sensory)` → `v = v*(1-leak) + drive` → refractory neurons clamped to `v_reset`, counter−1 → `spike = v >= v_thresh` → reset `v`, `refr = 2`.
- [x] Propagation sums in ascending presynaptic order in f32 (identical to scipy's CSC-gather and CSR-matvec paths), so the spikes are bit-identical.
- [x] Slow global gain controller: `gain *= exp(gain_adapt*clip((target_p - frac)/target_p, -1, 1))`, clipped to bounds, `target_p = rate*dt/1000`.
- [x] Noise bank: `standard_normal(n*16, f32) * noise_std` drawn once from `default_rng(seed)`, read at `rng.integers(0, size-n)` per step. Rust reimplements `SeedSequence` + PCG64 + the NumPy float32 ziggurat (`fly_sim::rng`).
- [x] Sparse (≤10 % active, column gather) and dense (CSR) propagation paths: Rust uses a row-blocked CSC for sparse and CSR for dense, rayon-parallel.
- [ ] `dtype=float64` option (`KICK_THE_FLY_SIM_DTYPE`, `Settings > Brain > dtype`): the Rust sim is f32 only. **Review 2026-10-11:** still f32 only; `brain.dtype` is stored and has no effect (settings audit).
- [~] Individuality `D_post·W·D_pre` (`core/individuality.py:compute_fly_gains`): `fly_sim::lif::Individuality`; the normals are bit-exact, the final f32 `exp` agrees to ~1e-6 (NumPy's SIMD exp varies by CPU), so runs with individuality on are statistically, not spike-for-spike, equal. No whole-run golden for it yet; personality cards (`compute_personality_card`) are not ported.
- [x] `ActivityBuffer` (EMA rate τ=40 steps, 400-step raster, last-spike step): `sim.py:ActivityBuffer`.
- [ ] Backends other than the reference: Numba/torch/GL are replaced by rayon + (later) a wgpu/compute path. `backends.py:{detect_available_backends,auto_chain,create_backend,GLBackend}`. **Review 2026-10-11:** one CPU backend (rayon); `brain.backend` has no effect (settings audit). No wgpu compute path.
- [ ] Max flies per backend (`kick_the_fly.py:get_max_flies`), multi-fly batching, brain in its own process (`core/brainproc.py`; the Rust design uses a thread, see section 14). **Review 2026-10-11:** a fixed cap of 16 flies (`flies_play::MAX_FLIES`), one sim thread steps every brain; `brain.process` has no effect.

- [x] Simulation on its own OS thread at a fixed 200 steps/s timestep (`crates/game/src/sim_thread.rs`); the render thread only reads the latest published snapshot (a one-slot mailbox with recycled buffers, `snapshot.rs`; locks are held only for a pointer move) and sends commands over a bounded channel.
- [x] Dev builds use Bevy's `dynamic_linking` feature; release builds do not (`crates/game/Cargo.toml` feature `dev`).
- [x] Exact version pins in `Cargo.toml` (`bevy = "=0.19.1"`, no third-party Bevy plugins yet).
- [x] UI toolkit, audio, gamepad and video-recording crates: choose and pin when their feature is ported. **Rust:** UI: Bevy UI (text and nodes) + custom `UiMaterial` for the fly's eye; audio: `bevy_audio` (WAV assets + a streaming `Decodable`) and `cpal =0.18.2` for the microphone; physics: `avian3d =0.7.0` (built for Bevy 0.19; bevy_rapier3d 0.36 is too, avian was chosen for its ECS-native joints and `Forces` API); `bytemuck =1.25.2` for GPU buffers. ### Cannot be matched exactly
- **Text rasterization**: pygame renders hinted glyphs with FreeType; `ab_glyph` renders unhinted outlines. Widths and positions are identical (pygame's advances are a lookup table), edges differ by anti-aliasing (a few percent of text pixels).
- **Font**: Python used the first installed of Segoe UI, DejaVu Sans, Liberation Sans, Arial: the look depended on the OS. The Rust game bundles GNU FreeSans (what that list resolved to on the reference Linux machine) so all OSes look like it. FreeSans is GPL-3.0+ with the GNU font exception: **check this is acceptable for redistribution before a release**; swapping in DejaVu (permissive) changes only `assets/fonts/` and `crates/ktf_ui/data/advances.json` (regenerate with `legacy-python/make_ui_metrics.py`).
- **Veil**: pygame blends the dark veil in sRGB space, Bevy in linear light; the in-game veil alpha is 240 instead of 196 so the room is as dark as in pygame (measured within 3 levels).
- **Window**: the menu canvas is the window's logical size (Python: the fixed HUD surface scaled to the window), so layout is identical at 1280x720 and reflows like Python's at other sizes only approximately.

### Multiple flies (session of 2026-10-10)
Each fly body has its own brain: `fly::Slot` names it, the sim thread steps the focused brain plus `Multi.extras` every 5 ms (`Command::SpawnFly`,
`RemoveFly`, `FocusFly`, `PokeFly`, `KillFly`; the snapshot carries the focus and the other flies' group levels, `snapshot::OtherFly`). `flies_play`:
**N** spawns a fly (cap 16, GAME RULE; the new fly takes the focus), **F** (`cycle_fly`) cycles the focus (held 5 s), the focus otherwise follows the fly
nearest to you unless a challenge, training, the arcade or a dead world needs it to stay (`_update_focus`), **J** (`recall`) puts lost flies back,
a real bump between two flies pokes body and legs on both brains (`_fly_collisions3d`; the push-apart is the physics engine's). Hits, damage, death and
every environment poke inside the per-fly loops (`environment.rs`: wind, light, heat, taste, rain, fruit...) go to that fly's brain; the HUD, the brain
panel and single-brain features (surgery, memory, challenges, autopsy) follow the focused fly (the learning state moves with the focus). Checked in the
game (`KTF_FLIES=3` spawns three after start): HUD `flies 4/16 · #2`, four bodies reacting on their own brains, sim still 200 steps/s.
Looming (`senses.rs`) and smells are per fly too. **Saves hold every fly now:** `Command::ExportAll` -> per fly `f{i}_b_*` brain arrays, `f{i}_fly_p` (head, thorax, abdomen), health, yaw, dead;
loading puts each brain back (`ImportFly`) and each body where it was (`ResetFly::restore`), restores the surgery modes and cell-type switches, the arena,
the tool, kills and the pain level; checked in the game (`KTF_SAVELOAD_CHECK=1 KTF_FLIES=2`: 3 flies saved, `flies 3/16` after the load). A Python 3D
save loads its brains exactly and its bodies by their first three particles, health and yaw; timers, things in flight and the other 14 particles are
not restored. **Since:** the contraption's wind reaches every live fly's own brain, and the FOCUS note carries the fly's measured personality card label like Python's. **Not done:** the memory scent (the tool in hand near a head) is still observed by the focused brain only, the
arcade/tool wheel/puppeteer assume one fly, the personality card is not drawn on the bodies, the cap stays 16 (Python's CPU value; Numba raised it to the CPU count, the larva to 64) and is not adapted to the machine (each extra brain costs about 0.3 ms per step here, so ~16 flies still ran real time on

### The 2D game (`--2d`): decision
**Not ported, on purpose.** The 2D game is the original top-down pygame game (`game/kick_the_fly.py:Game`, about 7,000 lines, its own software renderer,
particle-spring body, HUD and tools). The 3D game superseded it in 3.0 and is the default; every Lab, arcade, challenge and persistence feature this port
has was ported from the 3D side, and the 2D game shares none of its rendering or physics. Porting it means a second renderer and a second physics
engine for a mode the Python game itself only keeps as a fallback when OpenGL 3.3 is missing (which wgpu/Vulkan/Metal/DX12 make moot).
What the Rust build does instead: `--2d` is accepted and ignored with a note; a 2D save is refused with its reason ("made in the 2D game"; the compat
check); the `--2d` rows of section 1 are written off with this reason, not ticked.

### What is deliberately not the same

* **The memory belongs to the focused fly.** Python gives every fly its own mushroom body memory (only the first is saved); Rust has one
  memory that follows the focus on the sim thread (`Command::FocusFly`), so AVOID / APPROACH / FLEE read the focused fly's.
* **Camera shake** (`shake_until`) was written by tools and hits but never read: it is applied now (uniform +-1 cm on the eye for 0.12-0.4 s,
  off with Reduced flashing).
